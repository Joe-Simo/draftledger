# JetBrains evidence

DraftLedger is checked with IntelliJ IDEA (build IU-263.7307.200, Linux) using its command-line inspector. The project model and the inspection profile live in `../.idea/`.

Honest scope of this evidence:

- The inspections are real IntelliJ IDEA runs. `inspect.sh` starts the IDE headless, opens the project ("Opening an existing project with .idea" in the IDE log), and runs the committed profile over `src/`. The raw JSON results and the IDE's own `inspect.log` are kept per run in `inspections/`.
- The `.idea/` files were written by hand (a minimal module, project and profile) and then opened by the IDE. They were not generated by a GUI session, so there is no `workspace.xml`, `vcs.xml` or window state. A GUI session is a separate step.
- No JetBrains account, license or trial was used. JavaScript, TypeScript, HTML and CSS inspections are part of the free tier of IntelliJ IDEA.
- This setup was first built for the Fearplan prototype (merged into DraftLedger) and reused here.

## How the inspections run

`run-inspections.sh [label]` calls `bin/inspect.sh` on `src/` with `.idea/inspectionProfiles/Project_Default.xml` and saves one folder per run under `inspections/`. Set `IDEA_HOME` to another install if needed.
