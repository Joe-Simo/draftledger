# JetBrains evidence

DraftLedger is checked with IntelliJ IDEA (build IU-263.7307.200, Linux) using its command-line inspector. The project model and the inspection profile live in `../.idea/`.

Honest scope of this evidence:

- **GUI session.** On Nov 18 2026 the project was opened in the IntelliJ IDEA 2026.3 GUI (build IU-263.7307.200, Linux) and Code | Inspect Code was run with the Project Default profile over the whole project, tests included. The IDE wrote `.idea/workspace.xml` and `.idea/vcs.xml`. Screenshots: `../qa/ide-01.png` (editor with the project tree) and `../qa/ide-02.png` (Inspection Results tool window).
- **Headless runs.** `run-inspections.sh` starts the same IDE headless (`inspect.sh`) with the same committed profile, so the findings can be listed exactly and rerun. Raw JSON results and the IDE's own `inspect.log` are kept per run in `inspections/`.
- The first `.idea` files (module, project settings, profile) were written by hand before the GUI session and then opened by the IDE.
- No JetBrains account, license or trial was used for the headless runs. JavaScript, TypeScript, HTML and CSS inspections are part of the free tier of IntelliJ IDEA.
- This setup was first built for the Fearplan prototype (merged into DraftLedger) and reused here.

## What in `.idea/` is committed

| File | Committed | Why |
| --- | --- | --- |
| `inspectionProfiles/`, `misc.xml`, `modules.xml`, `draftledger.iml`, `vcs.xml` | yes | Shared project model and the profile the inspections use. |
| `workspace.xml` | yes | JetBrains guidance treats it as user-specific, but it is evidence that the IDE really opened the project. It holds no secrets: run configurations, the project id and one absolute path (`ts.external.directory.path`, a box path to `node_modules/typescript/lib`). The IDE rewrites it on every open, so expect noisy diffs. It is removed from `.idea/.gitignore` for that reason. |
| `shelf/`, `usage.statistics.xml`, `dataSources/`, `httpRequests/` | no | Per-user state, still ignored. |

## How the inspections run

`run-inspections.sh [label]` calls `bin/inspect.sh` on `src/` with `.idea/inspectionProfiles/Project_Default.xml` and saves one folder per run under `inspections/`. Set `IDEA_HOME` to another install if needed.

The one CSS error the GUI reported was **not reproduced** headlessly, even with `CssUnknownTarget`, `CssInvalidAtRule` and `CssUnknownProperty` forced on. `globals.css` already had the earlier `--font-geist-*` findings fixed in run m5.

### 2026-11-18-m6-fixed

Rerun after the fixes: no findings (only `inspect.log`). Markdown and grammar results are cached by the IDE per project, so a rerun straight after editing text files can report stale findings. The clean result was produced after clearing the project's cache folder under the IDE system directory and rerunning; it was repeated on unchanged files.
